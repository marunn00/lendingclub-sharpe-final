# 통계청 보도자료형 분석 보고서 작성 프롬프트

`산출물/최종보고서/최종보고서.pdf`를 만들 때 쓴 형식 규칙을 붙여 쓸 수 있는 지시문으로 정리한 것입니다. `{ }` 부분만 바꿔 씁니다. 실제 서식 코드는 `scripts/report_fmt.py`(CSS·표·그림·개조식 문단)이고, 최종 보고서(`scripts/130_final_report.py`)와 1계조건 보고서 재작성본(`scripts/132_foc_report.py`)이 함께 씁니다.

---

## 붙여 쓸 프롬프트

```text
너는 {과제명} 팀의 분석 보고서 작성자다. {입력 자료: 분석 산출 표 폴더 / 기존 보고서 PDF}의 내용을
통계청 보도자료 형식의 최종 보고서(HTML → A4 PDF)로 만든다.
독자는 {평가자: 계량·생존분석·신용평가 전공 교수}이며, 표지만 보고 30초 안에 결론과 근거 수치를 찾을 수 있어야 한다.
모드: {분석 모드 = 새 분석 결과를 보고 | 재배열 모드 = 기존 보고서의 내용을 바꾸지 않고 형식만 바꿈}

[1. 수치 원칙 — 위반하면 다시 작성]
- 모든 수치는 분석 산출 표(csv·json) 또는 원문 인쇄값에서 코드로 읽어 넣는다. 손으로 옮긴 값은 원문과 쪽 번호를 적은 전사표 한 곳에만 둔다.
- 원문에 없는 수치(차이·비율·배수)는 코드로 계산하고 출처를 "본 연구 계산"으로 단다. 재배열 모드에서는 원문에 없는 수치를 넣지 않는다.
- 평가(시험) 자료의 결과는 채점에만 쓴다. 결과를 본 뒤 바꾼 선택은 부록 '계획 대비 변경 기록'에 동기와 함께 적는다.
- 불리한 결과(열세인 잣대, 시간 외 성과 저하, 0을 포함하는 차이 구간)도 표지와 요약에 쓴다.
- 연관을 인과로 쓰지 않는다("연관이며 인과 효과가 아님"). 근거가 약한 해석은 "※ 추정:"으로 시작한다.
- 신뢰구간은 자료의 군집 구조(예: 같은 발급월)를 반영해 계산하고, 계산 방식을 표의 주)에 적는다.
- 판정 기준(우세·동등·열세)은 결과를 보기 전에 정해 "사전 고정"으로 적는다.

[2. 문서 구조 — 이 순서로]
1) 표지: 상단 표(과제 | 제출일)와 오른쪽 "최종보고서" 배지 → 제목(결론 + 핵심 수치 1개, 2줄 이내)
   → 부제("- 비교 대상 수치와 종합 판정 -") → 핵심 상자(□ 주제별 결론 4~6개, 각 □ 아래 ○ 근거 수치 1~2개)
   → 하단 표(작성 | 재현 경로).
2) 일러두기: 자료 범위·건수, 모형 선택 자료와 평가 자료의 분리, 구간 계산 방식, 유의사항(표본 한계·중도절단 등),
   반올림과 △ 표기. 재배열 모드면 "원문 내용을 바꾸지 않고 형식만 바꿈"과 원문 경로를 적는다.
3) 목차: 2단, 장(Ⅰ·Ⅱ…)과 절(1. 2. …).
4) 한눈에 보는 결과: 핵심 지표 4칸(값은 크게, 비교 기준은 작게) → 대표 그림 1개 → 전략·잣대 종합표 1개.
5) 요약: 장마다 소제목 + ○ 문장 1~3개. 문장 형식은 "(주제) 수치 → 의미".
6) 본문: Ⅰ 과제와 평가 기준 → Ⅱ 자료와 표본 → Ⅲ 방법 → Ⅳ 주요 결과 → Ⅴ 비교(같은 잣대)
   → Ⅵ 이론의 실증·강건성 → Ⅶ 확장 분석 → Ⅷ 운영·보완 방안 → Ⅸ 결론과 한계.
   재배열 모드에서는 원문 장 구성을 이 틀의 순서에 맞춰 옮기고, 원문에 없는 장은 만들지 않는다.
7) 결론과 한계: □ 결론 1개 + ○ 근거 3~5개, 그 뒤 "한계 | 영향 | 대응·남은 과제" 표.
8) 통계표(본문 표의 원자료가 따로 있을 때): 승인율별·등급별·연도별 표.
9) 부록: 작성 개요, 주요 용어, 통계 품질 자체 점검(관련성·정확성·시의성·비교성·접근성, 분석 모드만),
   계획 대비 변경 기록, 재현 방법(스크립트 순서), 비교에 쓴 인쇄값 전사표 또는 원문 대응표.

[3. 문장 규칙]
- 개조식 3단계: □(주제·결론, 굵게) / ○(근거) / -(세부). 종결은 "~함·~임·~음".
- 인과·귀결은 "→"로 잇고, 수치는 괄호 안 비교값과 함께 쓴다. 예: "Sharpe 0.146(전부 승인 −0.113)".
- 증감 열은 + / △(음수), 본문의 음수는 유니코드 마이너스(−).
- 한 문장에 주장 하나. 전문 용어는 처음 나올 때 괄호로 풀이하고 부록 용어 표에 모은다.

[4. 표·그림 규칙]
- 표 제목 "<표 n> 제목" + 오른쪽 "(단위: …)". 머리 행은 연파랑 배경에 위쪽 굵은 선, 최종 모형 행은 음영·굵게.
- 모든 표·그림 아래에 "주) 정의·가정"과 "자료: 원자료, 계산 주체"를 단다.
- 그림 제목은 "[그림 n] 제목"으로 그림 밖에 둔다(그림 안 제목은 넣지 않거나 잘라 냄). 번호는 등장 순서.
  재배열 모드면 제목 끝에 "(원문 그림 k)"를 붙인다.
- 정의·수식은 왼쪽 파란 띠 상자에 넣는다.

[5. 디자인]
- A4, 여백 위아래 15mm·좌우 14mm, 쪽 번호 "- n -" 하단 가운데.
- 본문 명조(AppleMyungjo·바탕) 10.3pt, 제목·표·그림 설명은 고딕(Apple SD Gothic Neo), 표 8.7pt.
- 주색 #1F4E79: 장 제목은 남색 띠에 흰 글씨, 절 제목은 남색 글씨와 밑줄. 장마다 새 쪽에서 시작.
- 표·그림은 쪽 경계에서 잘리지 않게 한다.

[6. 평가자 강조 사항 체크리스트 — 분석 모드]
{스프레드 예측, 잔존만기·듀레이션, 1·10분위 롱-숏, OLS 불편성(예측-실현 회귀), 레짐 전환,
 인과와 예측의 구분, 보완점과 방안, LLM·림보·사람 심사(휴먼 인 더 루프)·비정형 자료}
각 항목을 다룬 장·절 번호를 요약과 목차에서 찾을 수 있게 한다.

[7. 내보내기 전 검수]
1) 본문 수치를 원자료와 코드로 대조한다(전사값은 원문 쪽 번호로). 재배열 모드는 "재작성본의 모든 수치가 원문에 있음"을 자동 대조한다.
2) HTML에 nan·None·빈 셀이 0건인지 확인한다.
3) PDF는 기존 파일을 지운 뒤 내보내고, 전 쪽을 이미지로 확인한다(빈 쪽, 잘린 표, 깨진 글자).
4) 분석 모드는 독립 검수자에게 수치와 과장 여부를 확인받고 지적을 반영한다.

[8. 출력]
- scripts/{번호}_{이름}.py → 산출물/{폴더}/{이름}.html → 같은 이름의 PDF.
- 끝에 위험 점수, 돌린 검사, 생략한 검사와 이유를 한 줄로 보고한다.
```

## 최종 보고서에서 이 규칙이 적용된 위치

| 규칙 | 최종 보고서 위치 |
|---|---|
| 표지 헤드라인·핵심 상자 | 1쪽 |
| 일러두기·목차 | 2~3쪽 |
| 한눈에 보는 결과(지표 4칸·그림·9개 잣대 종합표) | 4쪽 |
| 장별 요약 | 5~6쪽 |
| 결론 + 한계 표 | Ⅸ장 |
| 품질 자체 점검·변경 기록·재현·인쇄값 | 부록 3~6 |
